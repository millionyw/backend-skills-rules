# LLM Wiki 知识库维护

## 依赖检查

本技能依赖 **obsidian-markdown** 技能（来源：kepano/obsidian-skills，Obsidian 官方语法规范）。执行流程：

1. 加载本技能后、执行任何写操作**之前**，检查当前会话可用技能中是否有 `obsidian-markdown`。
2. **有** → 先通过 Skill 工具加载它。此后所有页面语法（wikilink、embed、callout、properties/frontmatter）一律按其规范书写。
3. **无** → 按本技能"页面规范"一节的基础语法继续操作，并在首次回复中提示用户：
   > 可安装 obsidian-markdown 技能以获得完整 Obsidian 语法规范（https://github.com/kepano/obsidian-skills ）

## 概述

维护位于 `E:\2026_work_schedule\wiki` 的个人知识库（Obsidian vault），模式为 Karpathy LLM Wiki：

- **原始源**（项目目录中的任务、日志、周报等，不可变）→ **wiki**（由 AI 生成并全权维护的互相链接的 markdown 页面）→ **schema**（本技能即维护规范）。
- 分工：用户负责供料和提问；AI 负责全部读取、提炼、写页、交叉引用、索引、日志、体检。
- 核心价值：知识只编译一次、持续保鲜、可交叉引用、可溯源。wiki 是持久资产，不是每次问答的临时产物。

## 路径与结构

wiki 根路径固定为 `E:\2026_work_schedule\wiki`。目录用途：

| 路径 | 用途 |
|---|---|
| `entities/` | 实体页：项目、系统、服务器、人员、模块 |
| `concepts/` | 概念页：技术、方法、流程 |
| `summaries/` | 摘要页：项目状态、月度/阶段回顾 |
| `queries/` | 查询归档页，命名 `YYYY-MM-DD-主题.md` |
| `lint/` | 健康检查报告，命名 `YYYY-MM-DD-wiki健康检查.md` |
| `guides/` | 给人看的使用指南（不是操作规则来源） |
| `index.md` | 内容目录，每个页面必须登记 |
| `log.md` | 操作日志，只追加不删改 |
| `.obsidian/` | Obsidian 配置，**禁止改动** |
| `raw/` | 历史遗留空目录，**不使用** |

## 触发条件

**正向触发**：

- "入wiki"、"摄取到wiki"、"把这个文件/日志/周报编译进知识库"
- "查wiki"、"wiki里有没有关于X的记录"
- "wiki体检"、"wiki健康检查"、"lint wiki"
- "更新wiki的X页面"

**负向（不触发）**：

- 普通开发、运维、调试、任务管理（即便发生在项目目录内）
- 用户明确表示不需要动 wiki 时

## 操作一：摄取（ingest）

适用：把原始源编译进 wiki。步骤：

1. **确定范围**：用户指定文件则直接用；用户说"摄取最近变更"时，先读 `log.md` 找最近一次摄取涉及的日期，再按文件修改时间列出其后变化的源文件，向用户确认后再处理。
   **运维/ 禁止全量摄取**——必须指定到具体文件或子目录（如 `运维/209服务器-虚拟电厂/03_部署文档.md`）。
2. **读取提炼**：逐个读源文件，提取事实、结论、状态变化。
3. **落页**：判断触及哪些实体/概念/摘要页——
   - 页面已存在 → 更新：保留原有结构，追加新事实，修正过时说法并在改动处标注日期
   - 页面不存在 → 新建：遵循"页面规范"
4. **交叉引用**：新事实涉及其他已有页面时，在相关页面之间补 `[[wikilink]]`（双向）。
5. **更新 `index.md`**：新页面登记到对应分类；改名/删除的页面同步清理登记项。
6. **记录 `log.md`**：追加一条摄取记录。
7. **汇报**：列出新建/更新了哪些页面、各自改了什么。

节奏约束：一次摄取一个源文件批次（通常 ≤5 个文件），宁多次小批，勿一次吞全库。

## 操作二：查询（query）

适用：针对知识库提问。步骤：

1. **检索**：先 Grep/Glob 检索 wiki 页面并沿 `[[wikilink]]` 跟踪；wiki 覆盖不足时**只读**原始源补充。
2. **回答**：每个事实性论断后标注来源（相对路径，可带 `#小节`，如 `../tasks/虚拟电厂项目.md#技术栈`）。
3. **归档判断**：答案对以后有参考价值（技术选型分析、问题复盘、方案对比、状态梳理）→ 存为 `queries/YYYY-MM-DD-主题.md`，页首加 `## 查询信息` 元信息块（日期、问题原文、参考页面）；随手可答的琐碎问题不必归档。
4. 归档时更新 `index.md` 和 `log.md`。

## 操作三：整理（lint）

适用：健康检查。按顺序执行检查清单：

| # | 检查项 | 方法 | 处理 |
|---|---|---|---|
| 1 | 死链 | Grep 提取所有 `[[目标]]`，与实际 .md 文件名比对 | 当场修复（改链接目标；建占位页需用户确认） |
| 2 | 孤儿页 | 无任何页面链接到它的 wiki 页 | 只报告 |
| 3 | 索引一致 | `index.md` 登记项与实际文件双向比对 | 缺漏当场补 |
| 4 | 过期页 | 页面 updated 日期/变更历史早于相关源文件的最新修改 | 报告并列出应重读的源 |
| 5 | 矛盾 | 同一事实在不同页面说法不一致 | 报告；不确定时以原始源为准 |
| 6 | 旧页缺 frontmatter | 初始 9 页无 YAML 头 | 只报告，触碰时顺带补 |

处理原则：1、3 类机械问题**当场修复**；2、4、5、6 类内容问题**只报告**。全部发现写入 `lint/YYYY-MM-DD-wiki健康检查.md`（页首加 `## 检查信息` 块：日期、范围、统计），更新 `index.md` 和 `log.md`。

## 页面规范

- **文件名**：中文标题；带日期的用 `YYYY-MM-DD-` 或 `YYYY-MM-` 前缀；放入对应分类目录。
- **frontmatter**：新页面加轻量属性（`status`、`updated`、`sources` 列表；sources 用相对路径）。旧页面（无 frontmatter 的初始页）触碰时顺带补，不强制批量迁移。
- **语法**：wikilink、embed、callout、properties 按 obsidian-markdown 技能规范。该技能未安装时的基础规范：页内链接用 `[[页面名]]`，提示块用 `> [!note]`/`> [!warning]`，元数据用 YAML frontmatter。
- **结构惯例**（沿用现有页面）：`# 中文标题` 开头；结尾 `## 关联页面` 列出 `[[wikilinks]]`；状态用表格 + emoji（🟢🟡🔴）；实体页含基本信息/描述/变更历史。
- **粒度**：一页一主题，宁小勿大；页面超过约 150 行考虑拆分。

## log.md 记录规范

格式（沿用现有定义）：

```markdown
## [YYYY-MM-DD] 操作类型 | 描述

- 操作详情1
- 操作详情2
```

- 操作类型：**摄取** / **查询** / **整理** / **更新**
- 新记录追加到已有日志条目之后、"操作记录格式/操作类型"两个说明小节**之前**
- **只追加**：不修改、不删除历史记录

## 约束

1. **只写** `E:\2026_work_schedule\wiki\` 下的文件（`.obsidian/` 除外）；原始源目录（tasks/logs/reports/experience/ideas/运维/思路 等）**一律只读**，禁止修改、重命名、删除其中任何文件。
2. **禁止编造**：页面上的每个事实性论断必须可追溯到具体源文件；源里没有的不写；推断性内容必须明确标注"推断"。
3. **聚焦**：单次摄取必须有明确范围，禁止"把整个项目摄取进 wiki"式全量操作；运维/ 目录尤其如此。
4. **不动 `.obsidian/`** 配置。
5. **日期用绝对日期**（YYYY-MM-DD），今天的日期以会话环境为准，禁止凭猜测写日期。
6. **删除或合并页面需用户明确确认**；页面改名时必须全库更新所有入链。

## 与其他机制的衔接

- **work-log-prompt**：写完工作日志后可顺带问一句"是否摄取今日日志入 wiki"，用户同意才摄取。
- **auto-memory（memory/ 目录）**：存用户偏好与跨会话事实；wiki 存项目知识。两者不互相替代。
- **ops-safety-guard / linux-ssh-ops**：运维操作产出的文档是摄取源；体量大，按摄取范围约束处理。
- `wiki/guides/使用指南.md` 是给人看的概览；操作规则以本技能为准，两者冲突时以本技能为准。
